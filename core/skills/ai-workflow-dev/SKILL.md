# ai-workflow-dev 功能开发主链路

端到端功能开发编排器。**每个阶段必须先落盘产物、再经用户确认才能推进**，禁止跳阶段（用户显式声明跳过除外）。

## 阶段 0：环境与状态恢复

1. **公司环境探测**：检查当前项目是否为公司仓库（特征：pom.xml 含 `com.immomo` groupId，或目录名为 `ultron-*`）。
   - 是公司仓库 → 读取 ai-workflow-amar skill 并加载公司知识（组件清单、代码风格、结构惯例）。
   - 非公司仓库 → 仅使用通用层，不引用任何公司组件知识。
2. **状态恢复**：读取 `~/workspace/ai-workflow/runtime/tasks/CURRENT` 文件。
   - 存在且任务未完结 → 恢复上下文：读取该任务的状态文件与各阶段产物，从上次停留的阶段继续。
   - 上下文被压缩后重新开始工作时，**必须**先做本步骤，严禁凭摘要记忆续做。

## 阶段 1：需求录入

1. 输入形式：PRD 文档（PDF/Markdown，读取后结构化提取）、用户口述、Issue 链接。
2. 提取要素：背景、目标、功能点列表、非功能要求、验收标准、涉及的系统/仓库。
3. 显式列出**文档中不清晰的点**，作为下一阶段澄清的输入。
4. 产物：`01-requirement.md`（写入任务目录）。
5. 与用户核对提取结果，确认后进入阶段 2。

## 阶段 2：需求澄清

轻量苏格拉底循环，目标是把模糊需求变成可设计的规格，**不是无限追问**：

1. 评分 5 个维度（各 0-1 分）：意图、范围、非目标、约束、验收标准。
   模糊度 = 1 - (意图×0.3 + 范围×0.2 + 非目标×0.2 + 约束×0.15 + 验收标准×0.15)。
2. 每轮只问**一个**最弱维度的问题，优先用结构化选项（让用户选而不是让用户写）。
3. 默认上限 5 轮；模糊度 ≤ 0.25 或用户说"清楚了"即收敛。
4. **就绪关卡**（收敛前必须满足）：非目标明确、决策边界明确（哪些事 Agent 可自行决定）、至少一个关键假设被用户确认过。
5. 产物：`02-clarify.md`，含最终需求规格 + 残余模糊点声明。
6. 用户确认规格后进入阶段 3。

## 阶段 3：设计评审

调用 ai-workflow-design-review skill 的流程：产出设计文档 → 独立子 Agent 对抗性评审 → 按意见修订 → 用户批准。产物 `03-design.md`。

**轻量豁免**：若改动范围明确 ≤3 个文件且无架构影响，可征求用户同意后跳过本阶段，直接进入阶段 4，并在任务状态中记录跳过原因。

## 阶段 4：任务拆解与工时预估

调用 ai-workflow-estimate skill 的流程。产物 `04-tasks.md`，含：子任务清单（可分工粒度）、依赖关系、每个任务的工时预估与风险标注。协同开发场景下，明确标注哪些子任务可并行分给同事、接口约定是什么。

用户确认拆解后进入阶段 5。

## 阶段 5：编码实现

1. 将子任务转为 TODO 列表，逐项执行。
2. **ledger 纪律**：在任务目录维护 `ledger.md`，每完成一个子任务追加一行：做了什么、改了哪些文件、验证方式。
3. **红旗停表**：遇到以下情况立即停止并询问用户，禁止自行绕路：
   - 设计文档与实际代码结构冲突
   - 需要修改公共组件/其他人负责的模块
   - 需要引入新依赖
   - 同一错误修复尝试失败 2 次
   - 发现需求规格有遗漏（回到阶段 2 补充，而不是自行假设）
4. 公司仓库编码时必须遵守已加载的公司知识（异常处理、日志、告警、工具类选型）。

## 阶段 6：单元测试

1. 为新增/修改的核心逻辑编写单元测试（公司仓库注意：根 pom 默认 skipTests=true，运行测试需显式开启）。
2. 测试覆盖：正常路径、边界、异常分支（业务异常断言错误码）。
3. 无法单测的部分（如强依赖外部 RPC）明确列出，转为自测 checklist。

## 阶段 7：质量自检门

声明完成前必须全部满足并附**实际证据**（命令输出，不是"应该没问题"）：

- [ ] 所有 TODO 完成
- [ ] 编译通过
- [ ] 测试通过（附运行输出）
- [ ] lint/checkstyle 无新增问题
- [ ] ledger 与实际变更一致（对照 git diff 检查）

## 阶段 8：复盘关卡

**强制**。调用 ai-workflow-retro skill：生成执行日志 → 用户人工填写"本次 AI 的问题" → 生成改进提案。复盘未完成不得宣布任务结束。

## 任务状态管理

任务目录：`~/workspace/ai-workflow/runtime/tasks/{YYYYMMDD}-{slug}/`，结构：

```
state.md        # 当前阶段、各阶段状态
01-requirement.md
02-clarify.md
03-design.md
04-tasks.md
ledger.md
retro.md
```

- 进入/离开每个阶段时更新 `state.md`。
- 最新活跃任务写入 `runtime/tasks/CURRENT`（内容为任务目录名），任务完结后清空。
- 多个任务并行时，CURRENT 只记最近活跃的一个，切换任务由用户显式指定。

## 快捷模式

- `ai-workflow-dev --light`：跳过设计评审与拆解，适合 ≤3 文件的小改动（仍需澄清、编码、自测、复盘）。
- `ai-workflow-dev --continue`：直接恢复 CURRENT 任务。
- 任意阶段可说"跳过本阶段"，跳过必须记录在 state.md 且由用户确认。
