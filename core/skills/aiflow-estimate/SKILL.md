# aiflow-estimate 任务拆解与工时预估

把设计产物转化为可执行、可分工、可排期的子任务清单。

## 输入

- 设计文档（03-design.md）或用户口述的改动范围
- 若涉及多仓库/多服务，先列出改动面全景再拆解

## 拆解原则

1. **粒度标准**：每个子任务应在半天内可完成且可独立验证；超过则继续拆。
2. **依赖显式化**：标注任务间的前置关系，识别关键路径。
3. **分工友好**：标注每个任务适合"本人 / 同事 / 可并行"；跨人协作的任务必须附接口约定（入参、出参、错误码、超时语义）。
4. **联调与上线单独成任务**：不要把联调、提测、上线藏在开发任务里。

## 工时预估

1. 每个子任务给出三档估计：乐观 / 最可能 / 悲观（单位：小时或人天）。
2. 汇总时按最可能值求和，再乘风险系数：
   - 纯业务逻辑、改动面清晰：×1.2
   - 涉及公共组件/跨服务联调：×1.5
   - 涉及 unfamiliar 模块或新技术：×2.0，并建议先做技术验证任务
3. 显式列出**不含在预估内**的事项（如等待产品确认、依赖方排期）。

## 产物

`04-tasks.md`，结构：

```markdown
# 任务拆解 - {需求标题}

## 全景
改动涉及的仓库/模块/接口一览

## 子任务清单
| # | 任务 | 依赖 | 负责人建议 | 预估(乐观/最可能/悲观) | 风险 |
|---|------|------|-----------|----------------------|------|

## 关键路径
（串行链条，决定最短总工期）

## 接口约定（协作项）
（跨人/跨服务的契约细节）

## 汇总
总工时（最可能）：X 人天（已含风险系数）
不含在内：……
```

## 与用户的确认点

拆解完成后必须让用户确认：粒度是否合适、预估口径是否认可、分工建议是否采纳。确认后回传 aiflow-dev 主流程。
