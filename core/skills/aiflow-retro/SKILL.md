# aiflow-retro 复盘关卡

工作流可持续迭代的核心机制。复盘未完成不得宣布任务结束。

## 流程

### 1. 生成执行日志

从任务目录（或当前会话上下文）汇总：

- 走过的节点与各节点产物
- 关键决策记录（过程中的取舍）
- 返工/红旗停表记录（哪些地方卡住过、为什么）

写入 `runtime/tasks/{task}/retro.md` 的日志部分（模板见 `runtime/templates/log-template.md`）。

### 2. 人工反馈（必须由用户亲自填写，AI 不得代写）

向用户明确索取两项：

1. **本次 AI 的问题**：哪里理解错了、哪里风格不符、哪里过度设计、哪里遗漏。
2. **流程摩擦点**：哪个节点卡住、哪个产出质量低、哪个节点多余。

呈现方式：优先用结构化选项（AskQuestion 列出常见问题类别 + Other 自由输入）。用户明确说"没有问题"时记录"无"并继续，但**必须问过**。

### 3. 改进提案

基于人工反馈 + 返工记录，AI 草拟改进提案表：

| # | 改进项 | 落点（改哪个 skill/模板/知识文件） | 优先级 |

规则：

- 每条提案必须落到具体文件，禁止"以后注意"式空话
- 根因是模型能力而非工作流缺陷的，标注【非流程可解】，不生成提案
- 同类问题累计 2 次出现 → 优先级自动升高，提案改为修改 skill 正文而非补充说明

### 4. 人工采纳与落地

- 用户逐条确认采纳哪些。
- 采纳的提案**当场修改对应文件**，并在 `CHANGELOG.md` 追加一条（注明来源 retro 文件）。
- 修改 skill 正文属于高风险变更：只改增量部分，不重构无关内容。

### 5. 归档

- 更新任务 `state.md` 状态为已完结。
- 清空 `runtime/tasks/CURRENT`（若本任务是 CURRENT）。

## 定期聚类（可选）

累计 ≥5 份 retro 时，可触发聚类分析：按问题类别（需求理解/代码风格/过度设计/遗漏边界/流程摩擦）统计频率，找出系统性弱点，产出对 core/company 层的结构性改进建议。
