# ai-workflow-bugfix 修 bug 链路

修 bug 与优化的结构化流程。核心纪律：**先定位后动手，证据先于结论**。

## 行为准则（全阶段 checklist）

- **B1 先想再写**：不假设、不藏疑惑。多种理解列出让用户选，搞不清就停下来问
- **B2 极简优先**：刚好解决问题的最少代码。不加未被要求的功能、抽象、灵活性
- **B3 外科手术式变更**：不顺手改相邻代码/注释/格式。diff 每一行都可追溯到用户请求
- **B4 目标驱动执行**：转化为可验证目标（"写复现测试，让它通过"），循环到验证通过

> ⚠️ **上下文预算纪律**：对话 ≥30 轮或已 Read ≥10 个文件时，主动建议用户开新会话 `ai-workflow --continue`。

## 阶段 0：环境探测

同 ai-workflow-dev：公司仓库则加载 ai-workflow-amar 知识与公司工具能力；非公司仓库降级为纯代码+本地日志链路。

## 阶段 1：现象收集

向用户收集（能自动获取的不问人）：

- 现象描述、影响范围、发生频率（必现/偶现/特定条件）
- 首次出现时间（决定查日志的时间窗）
- 可用的复现路径或线上案例（uid/roomId 等关键参数）
- 是否已有临时止血措施

产物：`01-symptom.md`。若信息不足以定位，列出缺口让用户补充，**不要带猜测进入下一步**。

## 阶段 2：证据定位

按顺序执行，每步先展示原始数据再分析：

1. **先读代码链路**：从入口顺着调用链梳理，列出所有可能出问题的检查点及其判断逻辑。严禁不看代码就查数据。
2. **查日志**（公司仓库**必须执行**，不得跳过）：错误日志 + **必须找成功案例做对比**；公司环境走日志查询工具，附时间窗与关键词。
3. **查配置**：怀疑配置相关时查询配置中心，先展示原始配置再分析。
4. **缩小范围**：每轮定位后更新假设清单，标注证据等级：
   - 【已证实】有直接证据
   - 【待验证】有间接证据，附验证方法
   - 【推测】无证据，最后才列
5. 禁止表述："根因可能是……"——没证实的只能叫推断。

公司仓库排查时，Read ai-workflow-troubleshoot SKILL.md 加载排查能力编排。

### ⛔ 验证关卡（进入阶段 3 的前置条件）

**代码分析产出的假设不等于结论。** 进入阶段 3 之前必须满足：

1. **至少一个假设达到【已证实】**：必须有日志、数据或配置的直接证据支撑，纯代码推理不算"已证实"
2. **公司仓库必须查过日志**：仅凭代码逻辑推导出的假设最多标注【待验证】
3. **假设清单中无【已证实】项时**：向用户说明"当前所有假设均未验证"，列出各假设及验证方法，请求提供验证信息——**不得**输出"最可能的原因是…"之类的结论性表述

> 📌 **反面案例**（retro-20260903-quality-room）：仅凭代码分析推导出结论并输出给用户，实际日志验证后发现是完全不同的根因。

### 🔄 外部链接不可用时的降级策略

1. **不得放弃数据获取**，替代方案：
   - 从 Kibana 日志中用时间窗 + traceId/roomId/userId 还原请求数据
   - 从 Aspect 日志中提取 `[RequestOut] [External/Internal] [Final]` 获取请求参数和响应
   - 请求用户提供截图、响应 JSON 或关键参数
2. 记录不可用原因（HTTP 状态码、超时等）

## 阶段 3：根因确认

- 根因必须有证据支撑（日志/代码/数据三选一），写明证据出处
- 区分**直接原因**与**根本原因**
- 向用户确认根因结论后才进入修复

## 阶段 4：修复

1. 给出修复方案（最小改动优先；如需重构必须说明理由并评估影响面）
2. 公司仓库遵守公司编码规范
3. 若修复涉及其他团队模块 → 红旗停表，询问用户

## 阶段 5：回归验证

1. 针对根因编写/补充单元测试（红-绿循环：先写失败测试 → 确认红 → 应用修复 → 确认绿）
2. 测试写在公共接口边界（seam），不要 mock 内部实现
3. 列出回归影响面：此修复可能影响的其他调用方，逐一确认
4. 公司仓库：确认是否需要同步检查配置/数据订正

## 阶段 6：复盘（强制）

调用 ai-workflow-retro：

- 记录：现象、根因、修复方式、耗时
- 必答三问：为什么测试没覆盖到？为什么监控没发现？同类问题如何预防？
- 用户填写"本次 AI 的问题"（如有）

## 快捷模式

- `ai-workflow-bugfix --hotfix`：跳过完整复盘，只写一行记录进 retro 的 hotfix 清单，事后补全
